# Technical Test — Candidate Instructions

Welcome, and thanks for taking the time. This should take roughly **2–3 hours**.
We care far more about how you work than about how much you finish.

---

## 1. Getting started

You will need Docker (with the Compose plugin) and nothing else.

```bash
docker compose up --build
```

- UI: http://localhost:5173
- API docs: http://localhost:8000/docs

Click around: there is a side menu with a **Users** page (a table) and a
**Settings** page (where you can switch the interface language between English and
French). Read `README.md` for the project layout, then spend a few minutes reading
the code for the Users page end to end — model → schema → crud → router on the
backend, and view → `DataTable` on the frontend. The feature you build should look
like it was written by the same team.

The UI is **localized** with `vue-i18n`: user-facing strings are not hard-coded,
they come from `frontend/src/locales/en.json` and `fr.json` and are read with
`t('...')`. Switch the language on the Settings page and watch the Users page
update.

You edit code on your machine; both the API and the UI hot-reload, so you see
changes without restarting (the one exception is below).

## 2. What to build — a "Documents" feature

Add the ability to **upload a PDF and see it listed**, with some metadata that we
extract from the file itself.

### 2.1 The feature, from the user's point of view

1. A new **Documents** entry in the side menu.
2. A **Documents** page showing a table of everything uploaded so far.
3. An **"Add a document"** button that lets the user pick a PDF and upload it.
4. After upload, the document appears in the table. Some of its data is not known
   immediately — it is **extracted from the PDF** (see below) — so the row may
   start in a "processing" state and fill in once that finishes.

### 2.2 A document has these attributes

| Attribute         | Where it comes from                                            |
| ----------------- | -------------------------------------------------------------- |
| `id`              | generated by the database                                      |
| `name`            | the uploaded file's name                                       |
| `uploaded_at`     | when it was uploaded                                           |
| `number_of_pages` | **extracted from the PDF**                                     |
| `size`            | the uploaded file's size — your call on the unit (bytes / KB / MB) and where you compute it; justify your choice |

### 2.3 Localize your new strings

The app is translated (see section 1). Any label you add — the menu entry, the page
title, the table headers, the upload button — should go through `t('...')` with
entries in **both** `en.json` and `fr.json`, not be hard-coded. Switching the
language on the Settings page should translate your Documents page too.

### 2.4 Nice-to-have 

Generate a **thumbnail image of the first page** during processing, save it to the
shared `media` volume, and show it in the table. The infrastructure is already
there: anything written under `MEDIA_DIR` is served by the API at `/media/<file>`.
